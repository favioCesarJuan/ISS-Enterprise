# Security Policy

## Supported Versions

We actively provide security fixes and defense updates for the following versions:

| Version | Supported          |
| ------- | ------------------ |
| 1.2.x   | :white_check_mark: |
| < 1.2.0 | :x:                |

## Reporting a Vulnerability

The ISS-Enterprise bridge crew takes security seriously. If you discover a security vulnerability, we appreciate your help in disclosing it to us responsibly.

### 🛡️ Private Vulnerability Reporting (Recommended)

Please submit your report through GitHub's **Private Vulnerability Reporting**:
👉 [Report a Security Vulnerability](https://github.com/favioCesarJuan/ISS-Enterprise/security/advisories/new)

Submitting through this private channel ensures:
- The issue is kept strictly confidential until a patch is developed and verified.
- Direct collaboration with the project maintainer within a secure advisory workspace.
- Proper credit and CVE assignment upon coordinated release.

### What to Include in Your Report
To help us investigate and remediate the issue rapidly, please include:
1. A clear description of the potential vulnerability.
2. Steps to reproduce or a minimal proof of concept (PoC).
3. The affected component or hook (e.g., `tasha-security-shield.js`, `generator.js`, CLI commands).
4. Any proposed remediations or defensive mitigations.

### Response Timeline
- **Initial Acknowledgment**: Within 48 hours.
- **Triage and Assessment**: Within 5 business days.
- **Patch Release**: Coordinated with the reporter as soon as validation passes our automated tactical CI pipeline.

Thank you for helping keep ISS-Enterprise and the open-source community secure!
