## 1. Skill Management Lifecycle

Autonomous coding agents perform best when provided with modular, domain-scoped instructions. Uncurated skills lead to prompt bloat, contradictory directives, and attention degradation. ISS-Enterprise manages skills dynamically.

### Creating Custom Skills

You can forge a new specialized operational skill at any time via the tactical CLI:

```bash
# Recommended with pnpm:
pnpm dlx iss-enterprise skills create <skill-slug>

# Or via npx:
npx iss-enterprise skills create <skill-slug>

# Example:
pnpm dlx iss-enterprise skills create database-migrations-guard
```

This creates a dedicated directory and instruction manifest:
```text
.agents/skills/database-migrations-guard/
└── SKILL.md
```

### Anatomy of a `SKILL.md` File

Every skill generated by ISS-Enterprise uses strict YAML frontmatter paired with tactical directives:

```markdown
---
name: database-migrations-guard
description: Migration invariants and zero-downtime database schema rules managed by Lt. Cmdr. Geordi La Forge.
---

# ⚔️ DATABASE-MIGRATIONS-GUARD (Officer: Geordi La Forge)

## 🎯 Purpose & Scope
Specialized operational instructions for database-migrations-guard. Ensures all schema migrations are backwards-compatible and execute within isolated transactions.

## 📋 Directives & Best Practices
1. **YAGNI & Minimalism**: Ascend the Ponytail ladder. Do not over-engineer table structures.
2. **Backwards Compatibility**: Column drops must follow a two-phase deprecation timeline.
3. **Automated Verification**: Every migration must be accompanied by rollback automated tests.
4. **Security Shield**: Respect Lt. Tasha Yar's security perimeter rules.
```

### Anti-Collision Compaction

When projects accumulate dozens of raw skills (e.g. separate files for Tailwind, CSS Modules, accessibility rules, Semgrep, SQL injection checks, Vitest patterns), loading all of them into agent system prompts wastes thousands of tokens per turn and causes conflicting behavior.

Run the compactor to fuse overlapping skills into canonical pillars:

```bash
pnpm dlx iss-enterprise skills compact
```

The compactor engine (`src/skill-engine.js`):
1. Reads all directories in `.agents/skills/`.
2. Analyzes instruction tokens and identifies semantic domain boundaries.
3. Merges overlapping directives into the **6 canonical pillars**, deduplicating rules and outputting streamlined instruction manifests.

### The 6 Canonical Domains

| Canonical Domain | Assigned Officer | Operational Focus |
| :--- | :--- | :--- |
| `security-guardrails` | Lt. Tasha Yar & Worf | Command shields, Semgrep static analysis, OWASP Top 10, penetration defense |
| `design-system-and-ui` | Counselor Deanna Troi | Design tokens, WCAG AAA accessibility, styling hygiene (CSS Modules / Tailwind) |
| `code-health-and-ponytail` | Dr. Beverly Crusher | Ponytail protocol (YAGNI, minimal diffs), no continuous polling, clean architecture |
| `fullstack-architecture` | Lt. Cmdr. Geordi La Forge | Monorepos, package boundaries, Dockerfiles, build caching |
| `data-engineering-and-rag` | Lt. Cmdr. Data | Vector retrieval, ETL pipelines, Chroma/Qdrant, data streaming |
| `workflow-and-coordination` | Commander William T. Riker | Strict TDD, task breakdown, Vitest/Pytest/Playwright verification |

## 2. MCP Sensor Triad & Extensibility

The **Model Context Protocol (MCP)** gives AI agents standardized access to tools, databases, and system APIs. ISS-Enterprise configures the essential triad out of the box and provides a foundation for custom servers.

### The Indispensable MCP Triad

ISS-Enterprise identifies three sensor capabilities that every dreadnought requires:

1. **Long-Range Sensors (`context7`)**:
   Retrieves official, live 2026 documentation for libraries and APIs. Prevents hallucinations for recently released framework APIs (Next.js App Router, Astro 4/5, Tailwind v4).
2. **Enterprise Archives (`codebase-memory-mcp`)**:
   Maintains a persistent AST knowledge graph and runs Cypher queries to trace call chains, callers, and dependencies before refactoring.
3. **Subspace Communications (`github`)**:
   Automates pull requests, commits, issue auditing, and automated code review comments.

### Generating Configuration

Generate the standardized configuration file for your project:

```bash
pnpm dlx iss-enterprise mcps
```

This writes `.mcp/mcp-servers.config.json` in the root of your project:

```json
{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp"]
    },
    "codebase-memory-mcp": {
      "command": "npx",
      "args": ["-y", "codebase-memory-mcp"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}"
      }
    }
  }
}
```

### Adding Third-Party MCP Servers

To add specialized capabilities (e.g. database query tools, Docker orchestrators, browser devtools), edit `.mcp/mcp-servers.config.json` directly:

#### Example: Adding PostgreSQL and Docker MCP Servers
```json
{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp"]
    },
    "codebase-memory-mcp": {
      "command": "npx",
      "args": ["-y", "codebase-memory-mcp"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}"
      }
    },
    "postgres-db": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "postgresql://user:pass@localhost:5432/mydb"]
    },
    "docker": {
      "command": "npx",
      "args": ["-y", "mcp-server-docker"]
    }
  }
}
```

### Small Model Optimization

Heavy MCP servers with many tool definitions consume significant context tokens before an agent even starts thinking. For local or economy models (e.g. Qwen 7B, DeepSeek local, Ollama with <=32k context):

- ISS-Enterprise automatically substitutes heavy GitHub MCP definitions with the **native `gh` CLI skill**.
- The agent invokes `gh pr list`, `gh issue view`, and standard `git` terminal commands, saving thousands of prompt tokens.

## 3. Real-Time Security & Health Shields

During initialization (`iss init`), ISS-Enterprise deploys physical JavaScript hooks to `.agents/hooks/`. These execute deterministically to validate agent actions.

### Lt. Tasha Yar Security Shield

File: `.agents/hooks/tasha-security-shield.js`

Intercepts terminal commands proposed by agents and evaluates them against blacklisted patterns:

```javascript
const PROHIBITED = [
  /\brm\s+-[rR]f\s+[\/\*]/,       // Catastrophic root or wildcard deletion
  /\bcurl\b.*\|\s*(ba)?sh\b/,     // Piping untrusted remote scripts to shell
  /\bchmod\s+(-R\s+)?777\b/       // Insecure open permission granting
];
```

If an agent attempts a prohibited action, the hook aborts execution immediately with a tactical security alert.

### Dr. Crusher Health & Quality Check

File: `.agents/hooks/crusher-health-check.js`

Enforces code hygiene and prevents common agent anti-patterns:

1. **Continuous Polling Ban**: Detects and blocks `setInterval(() => fetch(...))` patterns. Enforces WebSockets, Server-Sent Events, or reactive event-driven patterns.
2. **Adaptive Styling Enforcement**: Respects the user's styling decision chosen in the advisor:
   - In **Strict Prohibition Mode**, any injection of `tailwindcss` or `nativewind` is rejected.
   - In **Permissive Mixed Mode**, both CSS modules and utility classes are validated.

### Captain's Log Writer

File: `.agents/hooks/captains-log-writer.js`

Maintains an append-only, immutable record of agent actions, architectural decisions, and verification test outputs in `.agents/captains-log.jsonl`.

### Automated Git Pre-Commit Binding (`.git/hooks/pre-commit`)

When you run `iss engage` (or `iss init`), the generator automatically inspects if the target project contains a `.git` repository. If detected, it arms `.git/hooks/pre-commit` with an automated execution wrapper:

```sh
#!/bin/sh
# 🛡️ ISS-Enterprise Tactical Git Pre-Commit Guardrail
node .agents/hooks/tasha-security-shield.js --test || exit 1
node .agents/hooks/crusher-health-check.js --test || exit 1
```

This guarantees that:
- Every `git commit` (whether triggered by an autonomous agent or a human developer) automatically runs security and health checks.
- If an agent generates forbidden styling imports or introduces code that fails security audits, Git immediately halts the commit with a non-zero exit code.

### Multi-AI Engine Contracts (`CLAUDE.md`, `.cursorrules`, `.windsurfrules`, `Agents.md`)

Different AI assistants read project governance from different files. ISS-Enterprise solves this fragmentation by dynamically generating tailored rule contracts during initialization:

| AI Assistant / IDE | Generated Contract | Enforcement & Purpose |
| :--- | :--- | :--- |
| **Claude Code & Claude Desktop** | `CLAUDE.md` | Primary guardrails: forbids destructive commands, mandates Ponytail anti-polling protocol, enforces styling policy and testing commands. |
| **Cursor IDE** | `.cursorrules` | Directs Cursor agents to respect Lt. Tasha Yar security boundary and Dr. Crusher code hygiene. |
| **Windsurf IDE** | `.windsurfrules` | Defines project-specific architectural boundaries and verification scripts for Cascade. |
| **Antigravity / Gemini / Generic** | `Agents.md` | Complete crew hierarchy, cognitive language protocols, and model budget mapping. |

## 4. Heterogeneous Fleet Orchestration & Context Budgeting

ISS-Enterprise supports mixed fleets across multiple AI providers:

- **Google Gemini**: Gemini 3.1 Pro, Gemini 3.8 Flash, Gemini 1.5 Pro
- **Anthropic Claude**: Claude 3.5 Sonnet, Claude 3.5 Haiku
- **DeepSeek**: DeepSeek-R1, DeepSeek-V3
- **Alibaba Qwen**: Qwen 2.5 Coder (72B, 32B, 7B)
- **OpenAI**: o1, o3-mini, GPT-4o, GPT-4o-mini
- **Local Ollama**: Any local model runtime

### Context Window Tiering

To avoid the twin traps of token budget exhaustion and attention degradation:

- **High-Reasoning Officers (>=128k - 1M tokens)**: Commander Riker, Lt. Cmdr. Data, Q. Assigned complex AST transformations, architecture reviews, and multi-file refactors.
- **Fast Economy Officers (8k - 32k tokens)**: Ensign Wesley Crusher. System prompts are quarantined under 800 tokens. Delegated isolated unit test execution, syntax checks, and single-file tasks.

### Cognitive Language Protocol

When interacting with non-English speaking developers (e.g. Spanish):

1. **Inbound/Outbound Communications**: The agents communicate with the human Captain in their natural language for maximum UX clarity.
2. **Internal Deliberation & AST Operations**: Model-to-model reasoning and code review traces run in English.
3. **BPE Token Savings**: English tokenization consumes **30% to 50% fewer Byte Pair Encoding (BPE) tokens** than romance or non-Latin languages for identical logic, directly lowering costs and speeding up response generation.
